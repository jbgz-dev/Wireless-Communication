# D2 静态 Validation 执行口径

1. 保持 D1 模型、特征配置和结果文件原样。核对 D2 静态点规划身份、四朝向、与 D1 训练点无交集，输出 split 标签对照表。D2 动态文件单独由 E 的交接说明处理。
2. 使用冻结的 D1 KNN/RF 做 2–6F 楼层、三区、楼层+Zone 验证。主点位口径：每朝向 Session 内去重，对模型逐扫描类别分数（未校准的 predict_proba）取平均，再对四朝向等权平均，独立取 floor、zone 最大分数；保留各朝向的代表指纹，即使另一朝向也有相同指纹。另报告 D1 可比的 Point 内去重单扫描准确率。任何拒识计为未正确。
3. 比较预设候选，训练 API 只接收 D1 去重数据；D2 用于选型、错误分析和补采。按 15 点楼层准确率、15 点联合正确率、去重扫描楼层准确率、扫描 Zone Macro F1 顺序比较；基线与新模型同口径，优先保留实际最好的方案。选型后的 D2 分数是开发验证成绩。
4. 交付 CSV 矩阵/明细、图、补采清单、可重训代码、D 的模型和配置。D3 预留全部 Test 点。当前 15 点不满足项目至少 50 个正式测试位置要求。

D 的实时接口每次只接收一条扫描，所以额外按扫描楼层准确率、扫描联合正确率、扫描 Zone Macro F1 的顺序选实时接入候选。四朝向等权结果另选静态对照。两者的选择均使用 D2 标签评分，D3 必须独立验证。

五层报告使用 2–6F 的完整点位。实时接入以 D2 回放比较原始分类器、15 个已知 AP 门限、AP 加 0.50 楼层投票双门限，报告可更新覆盖率、在更新条件下的正确率、全样本正确更新率。动态以每条 Run 冷启动按时序回放，分别标记 `ok`、`held` 和 `waiting`；保持历史值不能计作新楼层确认。D3 冻结模型和门限后，用 74 个五层点独立评分。课程基础项所需的三层测试记录仍按原规划保存。
