## 事件对齐

- 使用 `session_id` 在包内定位每条 Run，按 `t_elapsed_ms` 对齐事件和无线观测。四条垂直 Run 的 `move_start`、`move_end` 与路线标签一致，`move_end` 提供采集记录中的终点及参考时刻。用它计算的时差应标为相对人工标记的时差。
- 读入 [事件修正表](dynamic_event_overrides.csv) 后，以 `session_id`、`t_elapsed_ms`、`raw_event`、`raw_value` 匹配原始事件。`T8-ST08-VA01` 的 `floor_passed=2` 和 `floor_passed=1` 分别发生在 `move_start` 后 9.716 s 和 18.255 s，统一解释为 `stair_landing`，`effective_floor` 留空。`move_end=2` 保留。`T8-ST04-VA01` 的 `floor_passed=6` 比 `move_end=6` 早 11.777 s，按 `unconfirmed_terminal_floor_marker` 留存。
- 两条水平 Run 只有 `session_start` 与 `session_stop`。以这两个事件界定同楼层负例区间，统计假跳层，精确走动开始和结束时刻不可用。
- 传感器用 `t_ns` 记录，换算成毫秒后与 `t_elapsed_ms` 对齐。每条都有早于 `session_start` 的 `proximity` 和 `step_counter` 样本，评估时按 Run 时间边界筛选。六条记录均含加速度计和陀螺仪等数据，传感器清单未记录气压计。

## Wi-Fi 回调与评估范围

清单按 Run 内 `scan_id` 计数。213 次回调中有 205 次 `fresh=1` 且 `results_updated=1`，其中 203 次含 BSSID。两条电梯各有一次 `n_ap=0` 的 fresh 回调，应视为无 Wi-Fi 指纹。`T8-ST08-VA01` 和 `T8-HW01-VA01` 各有 4 次非 fresh 回调。楼层预测按项目规划使用无线测量，Run ID、目标楼层和人工事件用于对齐与评分。

包内只有观测与采集标签。终点正确率、自动更新成功率、更新延迟和水平假跳层仍需与 E 的预测日志对齐计算。这 6 条属于开发验证，D3 独立盲测另行评估。
