# 数据采集教程（从零开始，照着做）

这份教程从装软件开始，一直讲到把数据交给队友，每一步都写清楚了。
数据格式、采集计划等参考资料在 `README.md`。

---

## 第 0 步：需要准备什么

- 一台 Windows 电脑（已经装好 Python 3，就是你现在这台）
- 一部 Android 手机（Android 9 以上）和一根**能传数据**的 USB 线（有些线只能充电）
- 电脑能联网（第一次编译要下载约 1–2 GB）

---

## 第 1 步：安装 Android Studio（只需一次，约 30 分钟）

1. 打开 <https://developer.android.com/studio>，下载 Windows 版。打不开的话，可以用国内镜像 <https://developer.android.google.cn/studio>。
2. 运行安装包，一路点 **Next**，全部用默认设置。
3. 第一次启动时会出现 **Setup Wizard**：
   - 选 **Standard**；
   - 遇到 License 页面，每一项都点 **Accept**；
   - 点 **Finish**，等它下载完 Android SDK。

---

## 第 2 步：打开项目并编译（只需一次，第一次约 10–30 分钟）

1. Android Studio 欢迎界面点 **Open**，选择文件夹：
   `C:\Users\Lenovo\Desktop\wireless\FloorSenseCollector`
2. 如果弹出 **Trust Project?**，点 **Trust Project**。
3. 右下角会显示 **Gradle sync** 的进度条。**等它跑完**，第一次会比较久。
4. 如果弹出提示，建议升级 **Android Gradle Plugin**，点 **Don't ask again** 或者直接关掉，**不要升级**。
5. 同步完成后，点菜单 **Build → Make Project**。底部显示 `BUILD SUCCESSFUL` 就说明编译成功了。

**如果报错**：点底部 **Build** 窗口，把红色的错误信息复制给我（或者截图）。我会修改代码，你再点一次 Make Project。

| 常见报错 | 原因 | 处理 |
|---|---|---|
| `Could not resolve ...` / `Connection timed out` | 网络下载失败 | 换一个网络或开代理，然后点右上角大象图标 🐘（Sync Project） |
| `SDK location not found` | SDK 没装好 | File → Settings → Languages & Frameworks → Android SDK，勾选 Android 14 (API 34)，点 Apply |
| 其他红字 | 代码问题 | 发给我 |

## 第 3 步：把 App 装到手机上

### 方法 A：用 USB 线（第一部手机推荐）

**① 打开开发者选项**（不同品牌路径不同）：

| 品牌 | 路径 |
|---|---|
| 小米 / 红米 | 设置 → 我的设备 → 全部参数 → 连续点 **OS 版本**（或 MIUI 版本）7 次 |
| 华为 / 荣耀 | 设置 → 关于手机 → 连续点 **版本号** 7 次 |
| OPPO / 一加 / realme | 设置 → 关于手机 → 版本信息 → 连续点 **版本号** 7 次 |
| vivo / iQOO | 设置 → 系统管理 → 关于手机 → 连续点 **软件版本号** 7 次 |
| 三星 | 设置 → 关于手机 → 软件信息 → 连续点 **编译编号** 7 次 |
| Pixel / 其他 | 设置 → 关于手机 → 连续点 **版本号** 7 次 |

看到“您已处于开发者模式”就成功了。

**② 打开 USB 调试**：设置 → 搜索“**开发者选项**” → 打开 **USB 调试**。
小米手机还要再打开 **USB 安装**；如果有 **USB 调试（安全设置）**，也一起打开。这两项可能要求插 SIM 卡、登录小米账号。

**③ 安装**：
1. 用 USB 线连接电脑。手机弹出“允许 USB 调试吗？”，勾选“始终允许”，点 **允许**。
2. Android Studio 顶部的设备下拉框里会出现你的手机型号。
3. 点绿色三角 ▶ **Run**。手机弹出“是否安装”就点安装。
4. 手机上出现 **FloorSense Collector** 并自动打开，就完成了。

### 方法 B：发 APK 文件（第二部手机推荐，不用开 USB 调试）

1. Android Studio 菜单 **Build → Build App Bundle(s) / APK(s) → Build APK(s)**。
2. 完成后右下角弹出提示，点 **locate**，找到文件 `app-debug.apk`。
   （位置：`FloorSenseCollector\app\build\outputs\apk\debug\app-debug.apk`）
3. 用微信或 QQ 把这个文件发给第二部手机。如果微信把文件名改成了 `app-debug.apk.1`，先把文件名改回 `.apk`。
4. 在手机上点开文件，允许“安装未知来源应用”，然后安装。

## 第 4 步：手机设置（每部手机做一次）

1. **关闭 WLAN 扫描节流**（**最重要**）：
   设置 → 开发者选项 → 往下翻到“网络”部分 → 找到 **WLAN 扫描调节**（有的手机叫“WLAN 扫描限制”或“Wi-Fi scan throttling”）→ **关闭**。
   找不到这一项的话，可以在开发者选项顶部的搜索框里搜“扫描”。
   **注意**：Android 11 及以上，用 adb 执行 `settings put global wifi_scan_throttle_enabled 0` **没有效果**（系统已经不读这个设置了），即使查询结果是 0 也一样。只能在开发者选项里关。
   关掉以后，App 顶部的色条不应该再提示“扫描节流仍开启”。
2. **关掉省电限制**：设置 → 应用 → FloorSense Collector → 耗电 / 电池 → 选“**无限制**”或“允许后台活动”。
3. 下拉状态栏，打开 **定位、WLAN、蓝牙**。WLAN 不用连接任何网络。

## 第 5 步：第一次打开 App

1. 依次弹出权限请求，**全部选“允许”**：
   - 位置信息 → 选“**仅在使用该应用时允许**”，并且一定要选“**精确位置**”，不要选“大致位置”；
   - 附近的设备 → 允许；
   - 电话 → 允许（用来读取基站信号，不会打电话）；
   - 身体活动 → 允许（用来计步，判断是不是在走楼梯）。
2. 看 App **最顶部的色条**：
   - 🟩 **绿色**：一切正常；
   - 🟧 **橙色**：有警告。可以采集，但最好先按提示处理；
   - 🟥 **红色**：不能开始。按提示处理，比如去打开定位。

如果不小心点了“拒绝”：设置 → 应用 → FloorSense Collector → 权限，手动改成允许。

## 第 6 步：认识界面

| 输入项 | 填什么 | 例子 |
|---|---|---|
| 采集人代号 | 自己的代号，**不要写真名** | `P1` |
| 楼名 | 楼的编号 | `T5` |
| 楼层 | 现在所在的楼层，只填数字 | `3` |
| 区域 | 位置类型或课室号 | `corridor` / `lift` / `stair` / `305` / `bridge-T5T6` |
| 模式 | 静态定点 / 行走 / 跨层 | |
| 数据集 | 训练集 train 或测试集 test | |
| 持机方式 | 手机怎么拿 | 手持平放 |
| 点位编号 | 训练点用 **T** 开头，测试点用 **X** 开头 | `T01`、`X01` |
| 朝向 | 手机**顶部**指向哪个方向 | 北 N |
| 完成后自动切换朝向 | 训练点勾上（N→E→S→W），测试点不勾 | |
| 自动递增点位编号 | **默认不勾**。不勾时编号永远不会自己改，换位置后自己改编号 | |
| 目标扫描数 | 采够多少次新的 Wi-Fi 扫描后自动停止 | 训练 `5`，测试 `10` |
| 备注 | 特殊情况，可以不填 | `人多`、`电梯A` |

每次填的内容 App 会记住，下次打开不用重新填。

**开始前看一眼蓝色横条**：上面写着“下一条：T5 3F 点位 T01 朝向 N 手持平放 [train]”，就是这条记录会被标成的内容。对了再点开始。

“手机顶部朝向：xx° ≈ N” 是指南针读数。转动身体，让读数和你选的朝向大致一致就行。室内指南针有误差，差几十度没关系。

## 第 7 步：采集一个**训练点**（最常用）

举例：在 T5 3 楼电梯口采训练点 T01。

1. 填写：楼名 `T5`，楼层 `3`，区域 `lift`，模式 **静态定点**，数据集 **训练集 train**，持机方式 **手持平放**，点位编号 `T01`，朝向 **北 N**，勾选 **完成后自动切换朝向**，**不勾**“自动递增点位编号”，目标扫描数 `5`。
2. 站到 T01 的位置，手机顶部朝北，**平拿在胸前**。
3. 点 **开始采集**。
   - 屏幕显示“● 采集中”，“Wi-Fi 新扫描 1/5、2/5……”会逐渐增加；
   - **站着别动**，大约 15–30 秒。
4. 采到 5/5 时 **“叮”一声，自动停止**，朝向自动换成 **东 E**。
5. 转身让手机顶部朝东，再点 **开始采集**。然后依次采南 S、西 W。
6. 西 W 采完后，朝向回到北 N，提示“T01 已完成。换位置后请手动修改点位编号”。**编号仍然是 T01**。
7. （可选）在同一个点再采一次“裤袋”：持机方式选“裤袋”，手机放进裤袋，点开始采集。
8. 走到下一个位置，**把点位编号改成 `T02`，并修改“区域”**，看一眼蓝色横条确认无误，再继续采集。

如果你更喜欢编号自动加 1，可以勾选“自动递增点位编号”。开着朝向轮换时，它只会在 W 采完后才加 1。

**同时在平面图上标出点位**：每层电梯口一般贴着消防疏散图，拍下来，在照片上标出 T01、T02……的位置。

## 第 8 步：采集一个**测试点**

和训练点一样，区别在于：

- 数据集选 **测试集 test**；点位编号用 `X01`、`X02`……；
- **不勾选**“每点采 4 个朝向”；目标扫描数填 `10`；
- 朝向和持机方式**每个点随便换**，比如这个点平拿朝东，下一个点竖拿朝南，再下一个放裤袋；
- 测试点**必须和所有训练点至少相距 3 米**；
- 训练和测试**不要在同一天、同一时段采**。

如果不小心把训练点的编号用作测试点，App 会弹出 **“点位冲突（会造成数据泄漏）”** 并拒绝开始。这时换一个编号和位置就行。

## 第 9 步：采集**行走**数据

1. 先按下文在 **路线与节点** 录入一条路线，例如 `TW01`：A → B → C → D。
2. 模式选 **行走（同一层内）**，填写相同的楼名、楼层和路线编号，选择本次数据集与持机方式。
3. 站在 A，点 **开始采集**，App 自动记录起点 A，按钮显示 **到达 B**。
4. 正常走到 B 时点击 **到达 B**，到 C、D 时同样点击。整个过程不中断采集，不用等每次 Wi-Fi 扫描完成。
5. 误点可以立即按 **撤销上一个到达标记**，到达时重新点。起点不能单独撤销；连点间隔不足一秒会被忽略。
6. 到 D 后先点击 **到达 D**，再点 **停止**。一整条 A→B→C→D 是一个 Session，不要在 B、C 停止并重开。
7. 反向测 D→C→B→A 时新开一条 Session，开始前勾选 **反向行走**，站在 D 再按开始。不要在一条 Session 中直接来回走。

**完成状态：** 全部节点记录后停止，保存为 `complete`。节点未齐仍可提前停止，确认后保存为 `incomplete`，电脑工具默认跳过。新 Wi-Fi 扫描少于 5 次单独提示扫描不足，不会因为路线短就把已记录完整的路线当作未完成。

### 采集前设置路线节点（只记编号和顺序）

1. 主界面点 **路线与节点**，会自动打开当前楼层；路线编号选 `TW01`（没有就点 **+ 路线** 新建，和上面行走填的编号一致）。
2. 按正向行走的经过顺序添加节点：起点填 `A`，点 **添加节点**；再到转弯点、电梯厅入口等位置依次添加。编号会自动跳到下一个字母，不用填距离。
3. 顺序错了，点那一行的 **↑** 往前移。
4. 坐标 x、y 选填，先不用填。以后测了，点节点那一行补上。
5. 填错的节点：点右边 ✕ 删除（可以撤销），或者勾选多个后点 **删除选中节点**。
6. **复制节点映射** 会把这条路线的节点复制成 CSV，可以直接粘贴到微信或表格里。

### 导出给模型组

仍然点 **导出全部**。每条新版行走记录增加 `route_snapshot.json`（当次路线副本）、`node_visits.csv`（有效节点经过时间）、`node_marks.csv`（含撤销的动作记录）。以后补坐标或修改路线，不会改掉旧 Session 的路线副本。

模型组优先读取 `node_visits.csv`，不要把 `node_marks.csv` 中撤销过的到达再次算进去。节点的 `t_elapsed_ms` 与 Wi-Fi 的同名列及传感器的 `t_ns / 1000000` 对齐。`route_order` 是节点在路线管理里的正向顺序，反向行走时不变。

先试采一条 A→B→C，导出检查三个节点的时间是否齐全、两次点击之间是否有连续传感器数据，再扩大采集。完整原始导出包要保留。

## 第 10 步：采集**坐电梯 / 走楼梯**

举例：从 3 楼坐电梯 A 到 6 楼。

1. 模式选 **跨层（楼梯/电梯）**，楼层 `3`，目标楼层 `6`，方式 **电梯**，备注 `电梯A`。
2. 站在电梯口，点 **开始采集**，**原地站 10 秒**。
3. 点 **开始移动**，进电梯，按 6 楼。
4. （走楼梯时）每到一层的楼梯平台，点一次 **经过一层**（可选）。
5. 到 6 楼出电梯，点 **到达目标层**。
6. **原地再站 10 秒**，点 **停止**。听到“叮”一声就保存好了。
7. “楼层”会自动变成 `6`。改好目标楼层，就可以直接采下一趟，比如 6 → 2。

## 第 11 步：采错了怎么办

- **刚采完发现错了**（中途被人挡住、手机晃了等，数据本身不能用）：点 **删除上一条**。表单会恢复成被删除那条记录的编号和朝向，直接点开始重采就行。
- **数据没问题，只是标签填错了**（编号、楼层、朝向、train/test 填错）：点 **修改记录**，选中那条，改完点保存。
  - 只改 `meta.json` 里的标签，文件夹名和原始数据不变；
  - 修改前后的值会记在 `label_history` 里；
  - 如果改完会造成数据泄漏（同一个点同时出现在 train 和 test），App 会拒绝保存；
  - 之前已经导出到电脑的旧版本不用管，重新导出后，脚本会自动采用修改后的版本。
- **采到一半想放弃**：点 **停止**，确认“停止”。这条记录会被标记为 `incomplete`，处理时自动跳过。
- **一次删多条**：点 **批量删除记录**，勾选要删的记录（“勾选 incomplete”可以一键选中所有中途停止的），点删除，再确认一次。删除后不能恢复。
- **不要直接改电脑上的 meta.json**：下次导出时手机上的旧标签可能会把它覆盖掉。统一在手机上用“修改记录”改。

## 第 12 步：每天采完后，把数据拷到电脑并检查

### 导出

1. App 最下面点 **导出全部**，等“正在打包……”完成。
2. 弹出分享菜单，选 **微信 → 文件传输助手**，或者选 QQ、网盘。
3. 在电脑上下载这个 zip 文件。

### 解压

在 `C:\Users\Lenovo\Desktop\wireless\` 下新建文件夹 `data`，**每部手机、每天的 zip 各解压到一个子文件夹**，例如：

```
wireless\data\phoneA_1107\sessions\...
wireless\data\phoneA_1110\sessions\...
wireless\data\phoneB_1112\sessions\...
```

后一天导出的 zip 会包含前一天的数据，重复也没关系，脚本会自动去重。

### 检查

1. 在 `wireless` 文件夹空白处，按住 Shift 点右键 → **在终端中打开**（或“在此处打开 PowerShell 窗口”）。
2. 输入下面这行，按回车：

```
python FloorSenseCollector\tools\fs_tools.py check data
```

3. 怎么看输出：
   - **每层覆盖** 表：每层有几个训练点和测试点，用了哪些朝向、几种机型、哪几天；
   - **每栋楼**：测试点总数要 **≥ 50**；
   - **加分项数据准备**：`[OK]` 表示这个加分项的数据已经够了，`[..]` 表示还不够；
   - `[WARN]`：需要注意，但不一定要重采；
   - `[ERROR]`：**必须处理**，比如数据泄漏、扫到 0 个 AP。

把整个输出复制给我，我可以告诉你下一步还要补采什么。

### 交给训练模型的同学

```
python FloorSenseCollector\tools\fs_tools.py merge data -o wifi_scans.csv
```

生成的 `wifi_scans.csv` 就是训练用的表，发给负责模型的同学。

### 最后提交前（11/20 左右）

```
python FloorSenseCollector\tools\fs_tools.py anonymize data -o data_anon --salt 组内商量一个密码
```

`data_anon` 文件夹就是可以提交的匿名数据集。**salt 不要写进报告**。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| “AP 0”，提示最近一次扫描 0 个 AP | 定位没开，或者权限给的是“大致位置” | 打开定位；把权限改成“精确位置” |
| 新扫描很慢 | 看采集界面里的“Wi-Fi 诊断”这一行 | “系统限制”：回到第 4 步，在开发者选项里关闭节流；“正常”但还是慢：把输出发给我 |
| BLE 一直是 0 | 蓝牙没开，或者“附近的设备”权限被拒绝 | 打开蓝牙，并授予权限 |
| 基站一直是 0 | 没插 SIM 卡，或者“电话”权限被拒绝 | 不影响主要功能，可以忽略 |
| 采集时屏幕熄灭了 | 不应该出现，App 会保持亮屏 | 告诉我手机型号 |
| 静态采集一直采不满，不自动停 | 扫描被限制 | 点“停止”放弃这条，先检查第 4 步 |
| 找不到“WLAN 扫描调节” | 有的手机（Android 9 或部分定制系统）没有这一项 | 告诉我手机型号和 Android 版本 |
