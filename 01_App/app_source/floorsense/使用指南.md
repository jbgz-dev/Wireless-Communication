# BNBU-FloorSense 使用指南（v0.4）

BNBU-FloorSense 根据手机扫描到的 Wi-Fi 信号，自动判断你现在在 T8 楼的第几层（2F–6F），以及在这一层的哪个区域（西区、中区、东区）。坐电梯、走楼梯时，App 用手机的加速度计和陀螺仪识别跨层，到达后自动更新楼层。所有计算都在手机上完成，App 没有联网权限，不会上传任何数据。

> **v0.4 说明**
> - Wi-Fi 模型是 C 交付的冻结版 V1（随机森林，934 个 AP）。D3 静态测试（70 个 Test 点）：楼层 69/70（98.6%），其中 2–4F 51/52；区域 52/70（74.3%）。
> - 跨层检测：电梯用加速度计（起动、停止的加速度），楼梯用陀螺仪（每层平台的转身）。没有陀螺仪的手机会自动改用加速度计的旧规则。
> - 一次只走一层楼梯最准。连续走两层以上，App 可能只算一层，之后要靠 Wi-Fi 慢慢纠正。
> - **请在走廊里打开 App 并按"开始识别"。** 电梯厅、楼梯间信号弱，App 可能一直显示"—"，走到走廊就好。

---

## 1. 安装前的手机设置

每次使用前确认以下三项。不设置的话，App 扫不到信号或者更新很慢。

| 设置 | 怎么做 | 不做会怎样 |
|---|---|---|
| 关闭 Wi-Fi 扫描节流 | 设置 → 关于手机 → 连续点"软件版本号" 7 次打开开发者选项；然后在开发者选项 → 网络里关闭"WLAN 扫描调节" | 每 2 分钟只能扫 4 次，楼层更新很慢 |
| 打开定位 | 下拉状态栏打开"位置信息" | 安卓规定定位关闭时扫不到 Wi-Fi |
| 打开 Wi-Fi | 下拉状态栏打开 Wi-Fi，不需要连接任何网络 | 无法扫描 |

要求 Android 9 及以上。

## 2. 安装

1. 把 `BNBU-FloorSense-0.4-dashboard.apk` 传到手机上（微信、QQ、数据线都可以），点开安装。装过旧版的直接覆盖安装，**不要先卸载**，否则评估模式里没导出的数据会被删除。
2. 如果提示"禁止安装未知应用"，按提示允许这个来源后再装。
3. 第一次打开时，定位权限选**"使用时允许"**，并选**"精确位置"**。

桌面图标名字是 **BNBU-FloorSense**。它和采集 App（FloorSense Collector）是两个独立的 App，可以同时安装，互不影响。

## 3. 校准

**现场不需要校准。** 模型已经用 T8 2–6F 的训练数据训练好，装上就能用。

- 跨层检测的参数（每层约 4 米、楼梯转身的角度门限）都已固定在 App 里，不需要按人或手机调整。
- 如果以后 Wi-Fi 信号变化较大（例如学校更换路由器），需要重新训练模型：在每层固定的几个点用采集 App 重新采一次，由 C 用 `floorsense_c/d3_ready/d3_eval.py fit` 加入训练，导出新的 `wifi_model.json.gz`，替换 `src/main/assets/` 里的同名文件后重新打包。我们在 11-16 用 9 个点做过一次这样的校准，区域准确率从 74.3% 提到 80.0%，楼层准确率不变（见 C 的报告 `T8_Advanced5_同日校准对照.md`）。App 现在仍用没有校准的 V1。

## 4. 开始使用

1. 打开 App，等中间出现"模型：C 冻结版 V1（…）"，表示模型加载完成。
2. 在走廊里按 **"开始识别"**。几秒后屏幕中间出现楼层，例如 **4F**。
3. 拿着手机正常走动、坐电梯、走楼梯，楼层会自动更新，不需要任何操作。检测到一次跨层时手机会"嘀"一声。
4. 识别期间屏幕保持常亮。用完按 **"停止"**。

**持机方式：** 像看屏幕那样拿在手里。放进口袋或者甩手，跨层检测会变差。

## 5. 屏幕上每一项的含义

从上到下：

### 顶部色条：手机环境

| 显示 | 含义 | 怎么办 |
|---|---|---|
| 绿色"环境正常" | 设置都对 | — |
| 橙色"Wi-Fi 扫描节流开启" | 扫描节流还开着 | 按第 1 节关闭，否则更新很慢 |
| 红色 | 缺少精确定位权限，或定位、Wi-Fi 没开 | 按提示处理，然后切出 App 再切回来 |

### 大字楼层（如"4F"）

当前判断的楼层。

- 还没有结果时显示"—"。
- **字变成半透明**，表示这个数字是之前的结果，现在暂时没有新的判断，具体原因看下面的状态条。

### 楼层把握（如"楼层把握 0.97"）

App 同时用两种信息判断楼层：

- **Wi-Fi：** 每次扫描，随机森林给每一层打一个分；
- **运动传感器：** 识别出坐电梯或走楼梯后，App 知道上下了几层，就把之前的楼层按层数平移。

把握就是 App 认为"现在在这一层"的程度，0–1 之间。走廊里一般在 0.9 以上。

- 把握低于 0.5 时不显示楼层，大字显示"—"，下方写"还不确定在哪一层"。这通常是刚打开 App 时信号太弱。
- 把握不是正确概率，只能用来比较高低。

### 区域（如"区域：东区（0.67）"）

区域由同一个随机森林投票，选西区、中区还是东区。括号里是投票分：0.67 表示大约三分之二的树投给了东区。

| 区域 | 对应规划区字母 |
|---|---|
| 西区（West） | A、B |
| 中区（Middle） | C、D、E |
| 东区（East） | F、G、H |

D3 测试中区域对了 52/70（74.3%），中区最容易错（14/28）。演示时请把区域当作参考。

这次扫描把握不够时，区域这一行会空着，等下一次合格的扫描再显示。

### 状态条

| 状态 | 颜色 | 什么时候出现 | 楼层怎么处理 |
|---|---|---|---|
| 等待新的 Wi-Fi 扫描… | 灰 | 刚开始识别 | 还没有楼层 |
| 正常 | 绿 | 最近一次扫描有效 | 正常更新 |
| 信号不足：只认出 N 个 AP | 橙 | 认识的 Wi-Fi 少于 15 个，常见于电梯里、楼梯间 | 不用这次扫描，保持上一次楼层；跨层检测照常工作 |
| 信号弱，待更新 | 橙 | AP 够了，但这次扫描的楼层分数低于 0.50，常见于楼梯口、两层信号交界处 | 不用这次扫描，保持上一次楼层 |
| 扫描过期：超过 15 秒没有新扫描 | 红 | Wi-Fi 或定位被关掉，或者系统暂停了扫描 | 保持上一次的楼层；扫描恢复后自动回到"正常"，不需要重新按按钮 |

"15 个 AP、分数 0.50"是 C 在 Validation 上定的门限，D3 测试也是按这个规则评分的。

### 最下面的小字

- **已知 AP X / 扫到 Y**：这次扫到 Y 个 Wi-Fi，其中 X 个是训练时见过的。只有见过的才能参与判断。X 越大越可靠，走廊里一般有 30–100 个。
- **上次新扫描 N 秒前**：正常情况下在 0–5 秒之间变化。一直增加说明扫描停了。
- **扫描请求 N 次，被拒绝 N 次**："被拒绝"一直增加，说明扫描节流没关掉。
- **上次跨层：楼梯 +1 层（N 秒前）**：最近一次检测到的跨层。到达后大约 2 秒才会出现。

## 6. 跨层检测是怎么工作的

| 方式 | 用的传感器 | 判断方法 |
|---|---|---|
| 电梯 | 加速度计 + gravity | 电梯起动和停下时各有一次明显的上下加速度。把两次之间的速度积分得到移动距离，每 4 米算一层 |
| 楼梯 | 加速度计 + 陀螺仪 | T8 的楼梯每层都有平台，走楼梯一定会掉头转身约 180°，走廊是直的。加速度计先找出"在走路"的时间段；这段里有一次 ≥60° 的转身、合计转了 ≥150°，就算走了一层楼梯。从上往下看逆时针是上楼，顺时针是下楼 |

- 跨层途中扫到的 Wi-Fi 不参与判断，到达后从移动前的楼层平移，再用新的 Wi-Fi 继续修正。
- 加陀螺仪之前，楼梯用"走路上下晃动的幅度"判断，换一个人就不准；在 11 次走廊行走中误报了 10 次"走了楼梯"。加上陀螺仪后误报为 0 次。

## 7. 评估模式：测试 App 准不准

用来在已知位置上测试 App，记录结果并导出，可以直接用来写报告的准确率和混淆矩阵。

### 测试前先确认点位

- **正式测试**才用规划表里的 Test 点（TS 编号）。平时调试请用 Validation 点或者自己起的编号（如 `ACC-F3-01`），不要提前用掉 Test 点。
- 同一个位置只用一种用途，不要既当训练点又当测试点。

### 操作步骤

1. 先按"开始识别"，确认状态条是绿色。
2. 走到测试点，**先站 10 秒**。
3. 填三项：
   - **测试点编号**，如 `T8-F3-C-TS01`；
   - **真实楼层**，填数字，如 `3`；
   - **区域**，从下拉框选 West、Middle 或 East，不确定就选"Zone 未知"。
4. 按 **"记录这个点"**。按钮显示"记录中 1/5、2/5 …"。期间请站着不动，持机方式和平时一样。
5. 大约 10–20 秒后手机"嘀"一声，表示这个点记录完成。下方会更新累计结果，例如：

   ```
   已记录 6 个点，界面楼层正确 5 个（83.3%）
   单次扫描 30 次，正确 26 次（86.7%）
   混淆（真实→显示）：3→3:2  4→2:1  4→4:1  5→5:2
   ```

   - **界面楼层正确**：以记录结束时屏幕上显示的楼层为准，一个点算一次。这是报告里主要用的数字。
   - **单次扫描**：每次扫描单独判断的正确率。
   - **混淆**："4→2:1"表示真实在 4 楼、显示成 2 楼的情况有 1 次。

6. 走到下一个点，从第 2 步重复。
7. 记录中途想放弃，再点一次按钮（此时显示"点击取消"），这个点不会计入结果。

### 导出

按 **"导出评估数据"**，选微信、QQ 或邮件发到电脑。zip 里有：

| 文件 | 内容 | 用途 |
|---|---|---|
| `points.csv` | 每个测试点一行：编号、真实楼层、显示楼层 | 算准确率和混淆矩阵 |
| `predictions.csv` | 每次扫描一行：单次预测、屏幕显示和状态 | 分析具体哪里错 |
| `wifi.csv` | 原始扫描，格式和采集 App 相同 | 以后换了模型可以离线重新评估，不用再去现场 |
| `meta.json` | 手机型号、Android 版本、模型名 | 对比不同手机时用 |

> **注意：评估数据存在 App 自己的文件夹里，卸载 App 会一起删除。** 每次测完请及时导出，升级 App 时用覆盖安装，不要先卸载。

每次打开 App 后第一次按"记录这个点"，会新建一个评估文件夹，导出的是这个文件夹里的数据。

## 8. 回放模式（给开发人员）

用已经采集好的 session 数据，在手机上重新跑一遍识别逻辑，检查结果是否和电脑上一致，也方便测试算法。不需要去现场。

1. 在 App 里先按一次 **"回放全部 session"**。App 会建好文件夹，并显示路径。
2. 在电脑上用 adb 把采集 App 导出的 session 文件夹推到这个路径：

   ```bash
   adb push <session文件夹> /sdcard/Android/data/edu.bnbu.floorsense.app/files/replay/
   ```

3. 再按 **"回放全部 session"**，几秒后显示结果表。session 里要有 `wifi.csv` 和 `sensors.csv`（加速度计、gravity、陀螺仪）：

| 列 | 含义 |
|---|---|
| 检测 | 传感器检测到的跨层，例如"电梯-2"、"楼梯+1"，平地行走是"无" |
| 纯Wi-Fi | 只用 Wi-Fi 时界面楼层的准确率 |
| 融合 | Wi-Fi + 运动传感器时界面楼层的准确率 |
| 到达后 Wi-Fi / 到达后融合 | 只看到达目标楼层之后的扫描 |

回放时 App 不知道起点楼层，从"—"开始，界面显示"—"算错。移动途中（开始移动到到达之间）的扫描不计分。到达后录制太短（不到 2 秒）的 session，跨层可能来不及确认。

## 9. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 一直显示"—"和"等待新的 Wi-Fi 扫描" | 定位或 Wi-Fi 没开，或者没给精确位置权限 | 看顶部色条的提示 |
| 楼层更新很慢，"被拒绝"次数在增加 | 扫描节流没关 | 按第 1 节关闭 |
| 一直显示"—"（"还不确定在哪一层"） | 在电梯厅、楼梯间打开的 App，信号太弱 | 走到走廊，几次扫描后就会显示 |
| 经常显示"信号弱，待更新" | 站在楼梯口或两层信号交界处 | 往走廊中间走几步 |
| 跨层后楼层没变 | 跨层没检测到，例如手机在口袋里乱晃、电梯起动时晃手机、楼梯平台没有转身 | 到走廊后 Wi-Fi 会逐渐改正 |
| 连续走了两层楼梯，只加了一层 | 已知局限：一整段连续行走只算一层 | 到走廊后 Wi-Fi 会逐渐改正；演示时一次走一层 |
| 模型加载失败 | 安装包不完整 | 重新安装 APK |
| 导出后找不到之前的数据 | 卸载过 App | 数据已随卸载删除，以后用覆盖安装 |

## 10. 隐私

- App 没有联网权限，所有识别都在手机上完成，不会上传任何数据。
- App 只读取 Wi-Fi 信号的设备地址（BSSID）、信号强度和运动传感器读数，不连接任何网络，也不读取通话、短信或文件。
- 导出的 `wifi.csv` 里有周围 Wi-Fi 的设备地址，请只在项目组内部分享。对外提交前用 `tools/anonymize_dataset.py` 匿名化（见项目根目录 README）。
