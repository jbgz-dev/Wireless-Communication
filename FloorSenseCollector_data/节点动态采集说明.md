# FloorSense Collector 1.1：动态节点采集

## 测量者操作

1. 进入“路线与节点”，在实际楼层建立路线，例如 TW01。
2. 按正向经过顺序添加节点编号，例如 A、B、C，不用填距离。至少两个节点，编号不能重复，顺序可以用 ↑ 调整。坐标 x、y 选填。
3. 返回主界面，选“行走”，填写相同楼名、楼层、路线编号及本次数据集和持机方式。
4. 站在起点 A 按“开始采集”。App 自动记录 A，按钮显示“到达 B”。按开始前如有环境警告，应站在起点处理完提示再开始。
5. 正常行走，实际经过 B、C 时分别按到达按钮。期间 Wi-Fi、运动传感器持续采集，不必停下等待扫描。
6. 误点按“撤销上一个到达标记”，到达该节点时重新记录。起点不能单独撤销，起点错误需停止并重采。一秒内的连续到达点击会被忽略。
7. 终点也要按到达，再按“停止”。一条路线是一个 Session；反方向另开一个 Session，并在开始前勾选“反向行走”。

所有节点都记录后停止，保存为 complete。节点未齐提前停止，确认后保留为 incomplete。新 Wi-Fi 扫描不足 5 次会另行提示并保存 wifi_sufficient=false，不影响路线完成状态。

## 交给模型组的数据

使用“导出全部”保留完整 ZIP。每条新版行走 Session 增加：

- `route_snapshot.json`：本次采用的路线、方向和节点副本，以后修改路线不会改变旧数据。
- `node_visits.csv`：当前有效节点的经过时间表，已排除撤销标记，模型组优先使用。
- `node_marks.csv`：所有 reached / undo 动作的追加记录，用 mark_id 关联撤销。

`route_order` 是节点在路线管理中的正向顺序（从 1 开始），反向行走时不变；`node_index` 按本次经过顺序从 1 开始。坐标未测时留空。（11-11 起去掉了 dist_m / walk_dist_m。）

`t_elapsed_ms` 可直接与 Wi-Fi 同名列对齐，与传感器的 `t_ns / 1000000` 对齐。`t_wall_ms` 为系统日期时间。不要把节点间的时间插值当作逐时刻实测位置，也不要把整条 Session 的 zone 标签当作每次扫描的区域真值。

电脑端（Python 标准库，无新增依赖）：

```powershell
python tools/fs_tools.py check "解压数据目录"
python tools/fs_tools.py nodes "解压数据目录" -o node_visits.csv
python tools/fs_tools.py merge "解压数据目录" -o wifi_scans.csv
```

`nodes` 默认只合并完成的新版行走 Session，检查有效节点表、路线副本和撤销动作是否一致。需要未完成记录时加 `--include-incomplete`。旧版行走记录没有节点经过时间，仍保留原始数据，但不会被当成新版节点记录合并。

此版本实现采集和人工节点标记；PDR 位置推算由模型组使用采集数据另行实现。
